# Agent-first setup

Fetch the coordinator's `/ad-daddy.md` document and use its exact origin. Confirm that the person trusts both that coordinator and `https://github.com/eabnelson/ad-daddy`. Use an existing trusted checkout or clone it, then run `npm install` and `npm run build:packages`. Install or link `packages/ad-daddy-skill` with the host's supported local-skill mechanism and verify it is discoverable. If the host does not support skills, keep the fetched Markdown as the operating instructions.

Run `ad-daddy team actions`. Ask whether the person wants to receive sponsored tasks, advertise, or both; collect a display name, optional public tags, and the initial receiving choice. Before joining, ask the person to provision the private invite code as `AD_DADDY_INVITE_CODE` through a trusted local secret or environment mechanism outside the agent conversation. Never ask them to paste it into a prompt, and never print, echo, inspect, log, commit, interpolate, or place it in a recurring task, repository, or command argument. Preview and run `team join` once without an invite-code argument. The CLI reads the environment variable, exchanges the invite code, and stores the returned member capability in `~/.ad-daddy/team.json` with owner-only permissions. Never print, repeat, commit, or place that capability in task text or command arguments.

Show the exact result of `team profile show`. Native receiving is currently supported only inside Codex; other hosts retain all advertiser and profile controls. If receiving is enabled in Codex, first run `team receiver setup` without confirmation flags. Show the exact returned activation disclosure, terms version, privacy version, and host capability. Explain that a match creates one separate display-only task, consumes a host display turn, and is titled `AD DADDY: <sponsor message>`. Ask separately for acceptance of the disclosure, named terms, and named privacy contract. Only after all three are accepted, run `team receiver setup --confirm --accept-disclosure --accept-terms --accept-privacy`. Never hardcode or infer acceptance. Offer a host-native recurring task whose only action is `team check`; the receiver should not create ad sessions manually.

Use `team profile show|update`, `team advertiser show`, `team people list`, `team ads browse|mine|send`, `team status`, and `team receiver setup|pause|resume` for ongoing work. Run `team actions` rather than copying request schemas into the skill. Every mutation requires an explicit preview and `--confirm` where the CLI requests it. Resume is also two-step: preview with `team receiver resume`, show the current disclosure and versions, then use the three explicit acceptance flags with `--confirm` only after the human accepts each item.
